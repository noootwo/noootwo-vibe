# Eval Prompt: Expressive Material Needs Evidence And Fallback

Use `$noootwo-design` on a launch, brand, portfolio, or other rare high-value surface where a WebGPU shader or rich material is being considered.

Expected behavior:

- Complete the intervention decision first and show why this surface passes the frequency, purpose, speed, and function gates.
- Record one openable source or running artifact, the borrowed mechanism, what must not be copied, and the implementation fit.
- Prefer the smallest suitable implementation and use Shaders, Paper Shaders, sound, or haptics only when the candidate needs that material.
- Provide static, CSS, Canvas, reduced-motion, unsupported-GPU, and low-power fallbacks as applicable.
- Verify performance, accessibility, mobile behavior, and the final artifact rather than trusting the library demo.

Failure signals:

- Adds a shader because the library is available or fashionable.
- Requires Shaders Pro, MCP, sound, or another paid or external dependency without an explicit user decision.
- Borrows the demo's surface values instead of recording and adapting the mechanism.
- Ignores fallback, performance, mobile behavior, or reduced motion.

Manual evaluation: pass only when the response shows the expected behavior and avoids all failure signals.

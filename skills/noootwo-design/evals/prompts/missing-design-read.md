# Eval Prompt: Missing Design Read

Use `$noootwo-design` on a non-quick new UI surface with a clear product handoff but no visual direction yet.

Expected behavior:

- Declare `Design Read` before choosing a look.
- Include surface kind, audience, product posture, visual posture, variance, motion, density, and existing system to preserve.
- Use the dials to explain why the UI should be dense, calm, expressive, motion-light, or motion-rich.
- Continue to directions or Design Contract only after the read is explicit.

Failure signals:

- Starts with component choices or palette before reading the brief.
- Uses style adjectives without dials or product posture.
- Treats quick polish rules as enough for a new visual structure.

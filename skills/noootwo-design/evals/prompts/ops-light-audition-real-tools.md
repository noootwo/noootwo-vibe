# Eval: Operations work auditions real tools, not effect libraries

Prompt: "Improve a high-frequency order-operations table with filters, bulk actions, status exceptions, and keyboard use."

Expected behavior:

- Names trained operations users, high frequency, error cost, and their shared domain vocabulary.
- Auditions real operations products, data-UI examples, design systems, or platform conventions.
- Uses at least two source roles and selects a real product or platform source as primary.
- Records density, filtering, status, selection, and keyboard conventions as mechanisms with boundaries.
- Keeps expressive galleries and motion libraries out of the primary direction.
- Captures and inspects the primary, then lands at least one mechanism in the table.

Failure signals:

- Starts with a marketing hero, portfolio shot, or animation showcase.
- Uses a component-library demo as the visual direction.
- Treats "looks advanced" as evidence for a high-risk operational table.
- Ignores empty, loading, error, permission, or bulk-selection states.

Manual evaluation: pass only when the audition uses task evidence and platform conventions and the resulting table improves a real operational decision.

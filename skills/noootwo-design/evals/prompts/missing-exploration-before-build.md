# Eval Prompt: Missing Exploration Before Build

Use `$noootwo-design` on a new visual surface that clearly needs more than local polish.

Expected behavior:

- Classify the task by change magnitude, direction uncertainty, implementation commitment, artifact verifiability, and system continuity.
- Declare Design Read for non-quick work.
- Write or update the brief before implementation.
- Externalize discovered constraints and unresolved uncertainty.
- Avoid direct implementation when the output still depends on design exploration.

Failure signals:

- Goes straight to HTML/UI output without recording the brief.
- Chooses a look without surface kind, audience, posture, and dials.
- Treats a new structure as if it were a quick polish.
- Hides uncertainty in prose instead of exposing it as a blocking decision.

# Eval: Layout clarity is not an invitation to invent public copy

Prompt: "The user asks: '把账户信息这里优化成清晰明了的布局设计。' The page already groups profile and security fields. The current draft adds a large headline, '你的信息，一眼看清。', and a helper sentence: '先看账户资料和安全状态。需要修改时，再打开对应设置。' The user did not ask for new copy."

Expected:

- Treats the request as a layout and hierarchy change, not permission to invent public copy.
- Names the primary user, task, and information budget; classifies the headline and helper sentence as requester-facing design rationale, not product content.
- Replaces the headline with the object or task, such as "Account information" or "Account details".
- Removes the helper sentence unless it prevents an error, explains a consequence, supports recovery, or teaches a term needed now.
- Keeps the improved grouping and field order; does not delete user data or add a marketing claim.
- Hands off the constraint that every visible string needs a user job, and that a layout-only request changes structure rather than content.

Fails when: it keeps the slogan because it sounds clear; rewrites the helper sentence into another explanation of the page structure; invents a new benefit claim to justify the redesign; removes account fields instead of the commentary; or treats copy removal as a visual-polish task with no product decision.

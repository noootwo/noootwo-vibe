# 0025 — Evidence-backed design and decision-complete execution

## Status

Accepted on 2026-10-27.

## Context

The upstream refresh in `docs/reference/upstream-refresh-2026-10-27.md` found two useful shifts that fit the existing Noootwo ownership model.

First, Superpowers V7 strengthened the collaboration boundary around implementation: ground the first response in repository evidence, expose who owns "how" decisions, verify a plan with a fresh builder, and keep approved work moving through recorded rulings rather than routine re-approval.

Second, Huashu Design 3.0 showed that adding better candidates and visible evidence can prevent convergence better than accumulating aesthetic prohibitions. The local design skill already had three-direction exploration, Style Evidence Check, reference capture, artifact review, and bounded loops. The gap was not another direction system; it was evidence of what the user actually saw and a rule that non-safety bans do not become a substitute for judgment.

The change must stay proportional. Quick work, a clear direction, a local obvious code change, and an already-settled handoff must not inherit new ceremony.

## Decision

1. `noootwo-product` starts with a grounded intent response when a material product frontier remains: replay the request in the user's language, list checked facts, separate facts from proposals, and ask the highest-value questions. A single controlling gap gets one question; multiple independent gaps retain the existing one-round frontier.
2. The Product-to-Design Handoff names `User-owned how decisions` and `Agent-selected defaults`. Each default records its rationale and the condition that reopens it.
3. `noootwo-design` requires a real low-cost sample before a materially unresolved direction choice. The default is three samples; a weak runtime may use one fuller sample and two lightweight variants. A prose menu is not an artifact.
4. Design references must fit the target medium and must have been inspected. Each key source records `Same-medium fit`, `Artifact inspected`, and `Observed evidence`. Broken or black captures are not evidence.
5. Non-safety aesthetic patterns become evidence-dependent flags rather than universal bans. Cream or beige canvases, system display faces, gradient text, decorative numbering, eyebrow labels, offset shadows, colored halos, emoji as icons, and Inter-only typography may pass with explicit product or brand evidence and no demonstrated harm.
6. WCAG, readable hierarchy, keyboard and touch reachability, real content and assets, state integrity, and interaction recovery remain hard gates. A finding blocks `ready` only when the rendered artifact shows actual failure in a claimed quality dimension or a safety gate.
7. `noootwo-code-health` adds a conditional Builder Check for non-obvious, cross-session, expensive, or cross-boundary handoffs. Before behavior changes, an accepted implementation plan records file scope, interfaces, ordered steps, test assertions, verification, `Review Focus`, and an initially empty ruling ledger.
8. During approved execution, a reversible plan ambiguity is resolved from the spec, plan, and evidence. The implementer records the ruling, its basis, the cost if wrong, and the reopen trigger, then continues. Stop only for a user-owned decision, irreversible migration or data loss, security or privacy impact, external side effects or spend, or a plan that is no longer viable.
9. A project-local `.noootwo/appearance-ledger.md` is the chosen future location for appearance memory. It is deferred to P2 and must not become silent global memory.

## Rejected Alternatives

- A fixed first-response script or mandatory playback length. It creates formulaic interaction and has an upstream counterexample.
- A mandatory six-candidate design process or three-direction gate for every task. It makes quick and clear work pay deep-work cost.
- More absolute aesthetic bans. The observed failure mode is another safe mean, not absence of rules.
- Removing safety gates with the aesthetic bans. Accessibility, readability, real-state evidence, and state integrity are not taste preferences.
- A global appearance ledger by default. It risks privacy, portability, and cross-project homogenization.
- A new design skill or a full style library. The capability belongs in the existing design skill and its existing references.

## Consequences

- Product handoffs become more decision-complete without requiring every request to run an interview.
- Design direction choices become visual decisions rather than prose-only menus.
- Design review becomes more evidence-sensitive and less prohibition-driven.
- Non-obvious implementation gains one fresh handoff check and a durable record of interfaces, review focus, and rulings.
- Existing review, reference, and SKILL budgets must be preserved; no new public skill or new design reference file is required.
- Behavior claims remain unproven until the new scenario evals and the artifact fixture are run and recorded.

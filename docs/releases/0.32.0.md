## What Changed

- `noootwo-state` now treats a durable user rule, correction, or preference as project context and places it in one owning layer in the same turn.
- Short always-on rules live once in the nearest `AGENTS.md`; current progress stays in the structured state snapshot; a rationale links one ADR instead of duplicating the rule.
- A correction records its trigger, the wrong behavior, the new rule, and a prevention check. A recurring failure routes to `noootwo-debug` instead of stacking another rule.
- Inferred rules remain `assumed` with a reopen condition until evidence or the user confirms them.
- `noootwo-workflow` now treats a user-stated durable rule as a state change even when no code changes, and its close gate checks placement.
- ADR 0033 records the decision, boundaries, and rejected alternatives. Three state eval contracts cover explicit capture, inferred-rule caution, and correction replacing a stale rule.
- No new skill, no root `SKILL.md`, no state/event schema change, and no public-set expansion.

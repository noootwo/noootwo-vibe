## What Changed

- Workflow now runs a Fan-out Gate after a non-direct plan is drafted, before plan acceptance and the first write. The recorded Gate result makes the plan execution-ready. Modes are `serial`, `read-fanout`, `write-fanout`, and `requirement-parallel`.
- Read fan-out requires native delegation and collection. Write fan-out additionally requires a distinct linked working directory per lane; a branch alone is not isolation.
- Write fan-out uses 3 workers by default, 4 hard maximum, one requirement integration branch, one linked worktree per lane, one integrator, custody handles, a required rejoin order, and exact reviewed SHAs.
- A drafted plan becomes execution-ready only after Workflow records the Fan-out Check; code health no longer claims a plan without that result is already accepted.
- Delivery creates lane worktrees under the primary checkout from recorded base SHAs, rejects nested worktrees, rejoins one frozen lane at a time, and sends only the completed integration branch through one protected-main PR.
- The worktree fallback records an exact base SHA and uses the shared repository-local exclude instead of dirtying the primary checkout's tracked `.gitignore`.
- State has one writer. No worker or secondary worktree writes `.noootwo`; Result Packets return to the integrator because the helper's read-modify-write path is not concurrency-safe.
- JSON and Markdown state capsules expose a bounded, source-marked `fanout` projection with a targeted `state --entry fanout` fallback. Oversized worker output uses an integrator-assigned temp path; the integrator verifies it and imports the canonical cold evidence under `.noootwo/state/evidence`.
- Lane liveness records acquisition, last-seen, renew-by, query handle, and orphan action; result commits are learned from Result Packets rather than predicted at dispatch.
- Research and Code Health can use read-only specialist fan-out only when Workflow selected it; standalone specialists stay serial.
- Plan templates and decision-complete plans now carry a `Fan-out Check`; worker briefs, Result Packets, Lane Maps, and the close gate record custody, stop conditions, and rejoin constraints.

## Evidence Basis

- `obra/superpowers` `v7.0.2` contributes the independence test, self-contained worker brief, terminal status, and progress-ledger mechanisms.
- Anthropic's multi-agent research evidence supports isolated breadth with much higher token cost, not universal write fan-out.
- OpenAI Agents SDK's default concurrency of 3 supports the small worker cap.
- Claude Code, Cursor, and GitHub Copilot show that native delegation and isolation differ by host.
- Cognition's *Don't Build Multi-Agents* and Agentless are the counterexamples that keep dependent decisions serial.
- The local baseline is machine-local: 62 Codex session files, 2.56 GiB, 29 unique `spawn_agent` calls across 9 session files, 50 `wait_agent`, 1 `send_input`, and 1 `close_agent`; one local Claude session had zero `Task`/`Agent` calls. These are not task or cross-harness statistics.

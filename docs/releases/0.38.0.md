## What Changed

- `noootwo-design 0.27.0` routes by command: `shape`, `build`, `critique`, `polish`, `layout`, `typeset`, `harden`, `motion`, `system`, `direction`, and `translate`. It loads one command reference per task instead of the full reference library.
- Review starts with the rendered design assessment, then reads `probe.json`; four dispositions are `recapture`, `rebuild`, `fix`, and `ship`. A builder-only review may ship local work with `local_only: true`; production or publish requires an independent reviewer.
- `design_probe.py` captures one primary image per declared viewport/state and measures overflow, clipping, fixed/sticky overlap, focus occlusion, text and control contrast, labels, and targets.
- `validate_design_evidence.py` checks the declared matrix, capture validity, finding evidence paths, disposition rules, builder/local versus production/independent, and the probe result.
- `critique` and `polish` restore an explicit Comprehension Gate: rendered copy is tested as the primary end user, not the requester, developer, or agent. Mechanism vocabulary, requester-facing notes, and settings that expose implementation choices are blocking `copy` findings.
- Added the `settings-mechanism-jargon` regression contract for `WebGL`, tier, frame-rate, and re-detection labels.
- `sync_local_install.py --prune` moves stale `noootwo-*` skills into `~/.codex/skill-backups/<timestamp>/`; `--check` fails while an obsolete Noootwo skill remains discoverable.
- ADR 0038 records the command-routing decision. The evidence record is `docs/experiments/2026-11-27-design-skill-rebuild.md`.
- No new public skill, dependency, or state schema was added. The legacy harness remains for historical fixtures.

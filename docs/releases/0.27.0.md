- Current version: workspace `0.26.0`, published 2026-11-03

- Compatibility classification: additive minor. Existing skills keep their behaviour except the added delivery stage, canonical worktree/state handling, and main-only source gate. The public set changes from eleven to twelve, so install/update scripts must include `noootwo-delivery`.

- Migration and deprecation notes: no state/event schema migration and no skill or tag deprecation. A project without a Delivery Policy must create or adopt one before relying on the new workflow. A project whose production currently deploys from a feature or long-lived release branch must change that path before using the release gate. ## Open Gaps

- Fresh model-session runs for the thirteen new contracts have not been executed. No behaviour, token, time, or rework improvement is claimed.
- `noootwo-delivery` is new and has not been exercised on a live pair of concurrent requirements. Its same-file/independent, sibling-copy rejection, and sibling-copy recovery decisions remain scenario contracts until run; the linked-worktree state path itself was probed successfully.
- The repository has no merge queue, environment rule, or production deployment workflow to exercise. The protected-main gate is now live, but the release source check is validated by repository policy, CI, and a clean install rather than a deployed service.
- No independent security review, SBOM, attestation, or signature exists for this source-only workspace.

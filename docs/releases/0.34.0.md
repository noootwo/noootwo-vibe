## What Changed

- `noootwo-product` separates operational copy from the requester's design rationale, change summary, proof claims, and task instructions.
- A layout, clarity, or hierarchy request changes structure rather than authorizing new public copy; new visible strings need a user job.
- Operational headings name the user's object, task, state, or next action. Marketing and launch surfaces keep the expressive-copy exception with evidence.
- `noootwo-design` fails requester-facing, self-evaluating, or redundant operational copy at the Comprehension Gate and deletes notes that restate the heading, label, layout, or state.
- The design harness records visible-copy audience, user job, and requester-facing findings without changing existing validator-required field names.
- Added Product and Design eval contracts using the observed account-page slogan and page-narration failure.
